## Implemented in the Android repository

- [x] Native Kotlin/Jetpack Compose Material 3 application, not a webview shell
- [x] Warm-duotone SocialBoost interface and five-tab navigation
- [x] Shared FastAPI login/signup and encrypted Android Keystore session
- [x] Real dashboard and platform-specific analytics
- [x] Video picker, authenticated upload, server analysis polling, report, library and delete
- [x] Hook Lab and caption checks using existing real API
- [x] Predictions and Growth Coach including real model training/evidence
- [x] Platform comparison, YouTube channel lookup and historical CSV import
- [x] Draft create/list/edit/delete stored in the shared workspace
- [x] Creator-voice text variants on the actual trained local backend model
- [x] Real connected-account OAuth authorization link, manual/sandbox profiles, sync and disconnect
- [x] Sandbox calendar create/edit/cancel/delete with truthful statuses
- [x] Real shared account settings and preferred dark/light theme
- [x] Clearly unavailable Autopilot screen where production APIs do not exist
- [x] Gradle 8.11.1 wrapper generated by official Gradle; GitHub Actions debug APK and unit tests
- [x] HTTPS-only backend URL, no bundled credentials and no paid inference
- [x] No fabricated live analytics, rendering states or published posts

## Missing / blocked by existing shared backend

| Capability | Status | Work required |
| --- | --- | --- |
| Existing website baseline CI | Blocked | Correct npm lockfile mismatch in web repository and verify clean CI |
| Private video storage | Security blocker | Remove unauthenticated public media mount in web backend and test workspace isolation |
| Durable hosted database and uploads | Not verified | Confirm PostgreSQL, private object storage, backups and restart recovery |
| True server-side video rendering | Not implemented | Durable job API, independent free worker, FFmpeg and authenticated delivery |
| Three editable storyboard concepts | Not implemented | New briefs/concepts API and persistent scene manifests |
| Live Instagram/YouTube publishing | Not implemented | Official provider write scopes, consent, publish worker and real ID reconciliation |
| Autopilot review/pause/auto | Not implemented | Persistent state machine and permission-specific kill switch |
| Push notifications/offline sync | Not implemented | Requires reliable job model and storage reconciliation |
| Billing/subscriptions | Disabled by design | Only after real capacity and settled revenue |
| Production Android release | Not ready | On-device E2E, security audit, signing and store compliance |

The app uses the existing shared SocialBoost account and workspace. Server functionality depends on the actual live backend being reachable and retaining data. Do not confuse successful compilation with tested production readiness.

## Strict acceptance gates

1. CI must build a debug APK and pass Android unit tests.
2. Log in with a real test account and verify identical account state on website and Android.
3. Run upload, analysis, CSV import, drafts, calendar and account sync on physical Android devices.
4. Verify two workspaces never access each other's media or records.
5. Release automatic generation/publishing only after real server-generated MP4 and provider IDs are independently confirmed.
6. Never enable a paid provider automatically. Keep the entire early pilot at zero recurring infrastructure spend.
7. Document screenshots at small phone, regular phone and tablet sizes.

## Deployment model

GitHub Actions is for CI and APK assembly only. It must not become the commercial video-rendering infrastructure. Production server work remains in the shared FastAPI repository and its future independent worker.
